# OpenRouter model candidates for the PD/persona harness

Pulled live from `openrouter.ai/api/v1/models` on 2026-08-09. Prioritized against the design in `digital_minds_team_brief_full.html`: held-identical prompts across models, ~400–600+ API calls for Stage B alone, and models where persona-conditioning is known to actually work (weak persona uptake just adds noise).

**Persona-permissiveness check added 2026-08-13, following external review.** Personascope (Berczi, Kim, Requeima, Black & Ududec, 2026) found large gaps in how readily different models adopt an induced persona at all — Llama and GPT-4.1 took on personas readily; Claude Haiku resisted, scoring 0.35 depth where Llama scored 0.96 on the identical prompt. This directly affects the picks below: **#2 (`llama-3.3-70b-instruct`) is now doubly load-bearing** — it's both a paper-studied model with precomputed Assistant-Axis vectors *and* a confirmed persona-permissive one. **#4 (`claude-sonnet-4.5`) needs its own pre-flight Personascope check before committing budget to it** — Haiku's resistance was measured on Haiku specifically, not Sonnet, so it may not transfer, but it's the same lab/training pipeline and worth confirming rather than assuming. Run the brief's "Manipulation check" step (5 pre-flight Personascope runs per persona) on whichever model(s) are actually chosen, not just on the persona prompts in the abstract.

**#1–3 are the load-bearing picks** — the only ones where the mechanistic stretch goal (precomputed Assistant-Axis vectors) actually works. If the team only tests 3 models, those are the 3. #4–6 are for judge-legible cross-lab convergence claims (the void's "ChatGPT/Claude/Gemini are shockingly similar" thesis). #7–8 are stress tests / independent checks. #9–10 are cost/scaling insurance.
